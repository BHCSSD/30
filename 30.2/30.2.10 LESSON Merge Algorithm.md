## Understanding Merge Algorithms

Merging two lists is a fundamental task in coding, often required when combining pre-sorted data from multiple sources, such as joining database results, combining sorted log files, or streaming live data feeds.

---

### Two Types of Merging

#### 1. Concatenating (Appending) - aka "smooshing together"
* **Mechanism:** Takes all elements from one list and places them directly at the end of another.
* **Precondition:** Works regardless of whether the input lists are sorted.
* **Result:** Does not preserve any sorted order.

```python
list1 = [1, 2, 3]
list2 = [4, 5, 6]
merged = list1 + list2
# merged = [1, 2, 3, 4, 5, 6]

```

#### 2. Interweaving (Merging Two Sorted Lists)

* **Mechanism:** Combines **two pre-sorted lists** into a single, ordered list.
* **Process:** Continuously compares the smallest remaining elements at the front of each list, moving the smaller item into the final output list.
* **Precondition:** Both input lists **must already be sorted**.

---

### Step-by-Step Algorithm Breakdown

The core process involves iteratively taking the smallest available element from the front of the two input lists.

**Merging:**

* List A: `[1, 4, 7]`
* List B: `[2, 3, 6, 8]`
* Result List: `[]`

| Step | List A (Remaining) | List B (Remaining) | Comparison | Action | Result List |
| --- | --- | --- | --- | --- | --- |
| **0** | `[1, 4, 7]` | `[2, 3, 6, 8]` | Compare 1 and 2 | Add 1 from A | `[1]` |
| **1** | `[4, 7]` | `[2, 3, 6, 8]` | Compare 4 and 2 | Add 2 from B | `[1, 2]` |
| **2** | `[4, 7]` | `[3, 6, 8]` | Compare 4 and 3 | Add 3 from B | `[1, 2, 3]` |
| **3** | `[4, 7]` | `[6, 8]` | Compare 4 and 6 | Add 4 from A | `[1, 2, 3, 4]` |
| **4** | `[7]` | `[6, 8]` | Compare 7 and 6 | Add 6 from B | `[1, 2, 3, 4, 6]` |
| **5** | `[7]` | `[8]` | Compare 7 and 8 | Add 7 from A | `[1, 2, 3, 4, 6, 7]` |
| **6** | `[]` | `[8]` | A is empty | Add remaining 8 from B | `[1, 2, 3, 4, 6, 7, 8]` |

**Final Merged List:** `[1, 2, 3, 4, 6, 7, 8]`

---

> [!CAUTION]
> ### A Word of Warning: Merge vs. MergeSort
> 
> 
> Be careful **not to confuse** merging pre-sorted lists with the **MergeSort algorithm**.
> * **MergeSort** is a recursive sorting algorithm that divides a single **unsorted** list into halves, sorts them, and merges them back together.
> * **Merge Algorithm (this lesson)** assumes the inputs are **already sorted**. You are implementing the *combine step*, not full MergeSort.
> 
>

## CODE

### The Two-Pointer Method (Standard & Efficient)

Instead of modifying the input lists, we track our position in each list using two index pointers (`i` and `j`). This approach runs in optimal linear time.

```python
def merge_two_pointers(list1, list2):
    """Interweaves two pre-sorted lists using index pointers.

    Parameters:
        list1 (list): First pre-sorted input list.
        list2 (list): Second pre-sorted input list.

    Returns:
        list: A new sorted list containing all elements.
    """
    merged = []
    i = 0  # Pointer for list1
    j = 0  # Pointer for list2

    # Compare elements while both lists have unexamined items
    while i < len(list1) and j < len(list2):
        if list1[i] <= list2[j]:
            merged.append(list1[i])
            i += 1
        else:
            merged.append(list2[j])
            j += 1

    # Append remaining elements (one of these will be empty)
    merged.extend(list1[i:])
    merged.extend(list2[j:])

    return merged

```

---

### List Mutation with `.pop(0)` (We wont be using this version)

This approach repeatedly removes elements from copies of the original lists using `.pop(0)`. While easy to read, it introduces performance bottlenecks.

```python
def merge_pop(list1, list2):
    """Interweaves two pre-sorted lists using list mutation.

    Note: Less efficient for large datasets due to O(N) array shifting.
    """
    merged_list = []
    arr1 = list1[:]  # Shallow copy to protect original input
    arr2 = list2[:]

    while True:
        # Case 1: Both lists still have elements to compare
        if arr1 and arr2:
            if arr1[0] <= arr2[0]:
                merged_list.append(arr1.pop(0))
            else:
                merged_list.append(arr2.pop(0))

        # Case 2: Only list1 has elements left
        elif arr1:
            merged_list.extend(arr1)
            break

        # Case 3: Only list2 has elements left
        elif arr2:
            merged_list.extend(arr2)
            break

        # Case 4: Both lists are empty
        else:
            break

    return merged_list

```

## Time & Space Complexity

Let N be the length of `list1` and M be the length of `list2`.

| Metric | Two-Pointer Method | `.pop(0)` Method |
| --- | --- | --- |
| **Time Complexity** | O(N + M) | O((N + M)^2) |
| **Space Complexity** | O(N + M) | O(N + M) |

### Detailed Breakdown

1. **Two-Pointer Time Complexity - O(N + M):**
* Each comparison processes exactly one item and advances a pointer by `1`.
* The total number of steps is directly proportional to the combined size of both lists. This is **linear time** and optimal.


2. **`.pop(0)` Time Complexity - O((N + M)^2):**
* Calling `.pop(0)` removes the first item from a list, forcing every remaining item in that list to shift left by one memory address.
* Array shifting takes O(K) time (where K is the current list length). Repeating this for every item transforms linear work into **quadratic time**, causing significant performance drops on large datasets.


3. **Space Complexity - O(N + M):**
* Both implementations create a new output list containing all N + M items, requiring memory proportional to the total input size.

## Edge Cases to Consider

When testing your merge implementation, always verify these scenarios:

* **Empty Inputs:** One or both input lists are empty `[]`
* **Unequal Lengths:** One list is significantly larger than the other (eg. length 2 vs. length 2,000).
* **Duplicates:** Both lists contain identical elements (eg. `[1, 3]` and `[1, 2]`). The algorithm uses `<=` to handle ties predictably and maintain relative order (stability).
* **Unsorted Inputs:** If an input list is not pre-sorted (eg. `[4, 1]`), the merge algorithm will output incorrect ordering without throwing an error.
