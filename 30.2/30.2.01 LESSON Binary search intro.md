## Step 1: Concept Summary

### Sequential (Linear) Search

A **sequential search** (aka **linear search**) is the most basic search algorithm. It examines every element in a list **one by one** until it finds the target value or reaches the end.

> [!NOTE]
> **About Linear Search**
>
>   * Works on **unsorted** or **sorted** data
>   * **Simple** to implement, but **slow** for large lists
>   * Time complexity: **O(n)** (Linear Time)
>       * This means the algorithm's runtime increases **directly in proportion** to the number of items ($n$) in the list. If the list doubles in size, the time roughly doubles
>
> **Analogy:**
> You want to find the word "zebra" in a dictionary, but you start at "aardvark" and flip one page at a time until you see it.

### Binary Search

A **binary search** is an efficient-ish algorithm that **only works on sorted lists**. It repeatedly cuts the search area in half.

#### How It Works aka The Iterative Process:

1.  Identify the **middle element** of the current list/range
2.  If the middle element is the **target**, you're done, reutrn `mid`
3.  If the target is **too small** (less than the middle), eliminate the right half of the list
4.  If the target is **too big** (greater than the middle), eliminate the left half of the list
5.  Repeat steps 1-4 on the remaining half until you find the target or the search range is empty

> [!NOTE]
>
> **Why Binary Search is Better**
>
>   * Requires data to be **sorted**
>   * Each step **cuts the search space in half**
>   * Time complexity: **O(log₂ n)** (Logarithmic Time), extremely fast for large lists
>       * This means the runtime grows very slowly as the input size increases. Doubling the data (e.g., from 1 million to 2 million items) only adds one extra comparison step



* **Finding `target = 9` in the following **sorted** list:**
    ```python
    numbers = [1, 3, 5, 7, 9, 11, 13, 15]
    ```

| Step | Current Search Range               | Middle | Comparison (Target=9)   | Next Search Range        |
| :--- | :--------------------------------- | :------------- | :---------------------- | :----------------------- |
| 1    | `[1, 3, 5, 7, 9, 11, 13, 15]`      | **7** | 7<9 (Too small)     | Eliminate left half      |
| 2    | `[9, 11, 13, 15]`                  | **11** | 11>9 (Too big)      | Eliminate right half     |
| 3    | `[9]`                              | **9** | 9=9 (Match found)  | Done                     |

## Checkpoint

1.  What kind of list is required for binary search to work?

    <details>
    <summary>ANSWER</summary>

    A **sorted** list. Binary search only works when the list is in **ascending or descending order**.

    </details>

2.  How many elements does binary search eliminate on each step?

    <details>
    <summary>ANSWER</summary>

    It eliminates **half** of the remaining elements every time.

    </details>

3.  What is the time complexity of binary search?

    <details>
    <summary>ANSWER</summary>

    Binary search has a time complexity of **O(log₂ n)**.

    In binary search, $\log_2 n$ (pronounced "log base 2 of $n$") represents the maximum number of steps it takes to find your target. If you have $n$ items, the "log" tells you how many times you have to divide $n$ by 2 before you're left with just 1 item.

    </details>

5.  Which is faster for large datasets: linear search or binary search? Why?

    <details>
    <summary>ANSWER</summary>

    **Binary search** is faster because it divides the list in half each time, resulting in logarithmic time complexity, while sequential search checks every item one by one (linear time).

    </details>
