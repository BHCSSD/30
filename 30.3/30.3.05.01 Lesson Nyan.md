> [!NOTE]
> **INFO DUMP: Associative Relationships**
> * We are moving beyond designing a single class to structuring a program where one object relies on many others.
> * An **Associative Relationship** describes a connection between two separate classes.
>  * The most common type we use in programming is **Composition**, often called the **"Has-A"** relationship.
---
### **Composition: The "Has-A" Relationship**
* Composition means one class contains, owns, or manages instances of another class
  * **Generic Example:** A `Manager` object **Has-An** array of `Component` objects
  * **Example:** A `SnakeHead` object **Has-An** array of `TailSegment` objects

> [!NOTE]
> This structure is necessary to manage complexity. Instead of the main program handling hundreds of small entities, the **Manager** becomes responsible for coordinating all its **Components**
> 
---
### **Designing the System: Manager and Component Objects**

When using composition, we establish clear roles between the two classes: 
* the Component aka he managed object
* the Manager aka the initiator
---
#### **1. The `Component` Object aka The Individual Elements aka the tail**

* The Component is the simple, focused unit. 
  * It manages its own individual data and behavior
  * It is designed to be reusable and independent

* **Role:** To manage its own state (position, color, lifespan) and execute simple tasks
  * The `Component` does **not** need to know which `Manager` created it



```javascript
class Component {
  constructor(x, y, hue) {
    this.x = x
    this.y = y
    this.life = 255 //lifespan property
  }

  display() {
    //draws itself based on its internal properties
    fill(200, 100, 200, this.life)
    ellipse(this.x, this.y, 5)
  }

  updateState() {
    //changes its own state (fading, moving, etc)
    this.life -= 5
  }
}
```

#### **2. The `Manager` Object**

The Manager object is responsible for the overall system and controls the Component objects.

  * **Key Property: The Array** The Manager **must** have an Array property to hold all the instances of the Component class

```javascript
class Manager {
  constructor(startX, startY) {
    this.x = startX
    this.y = startY
    //The Manager has a list of Component objects
    this.elements = [] 
  }
  //... rest of the class below
}
```

> [!IMPORTANT]
>
> ### **The Role of the Manager**
>
> The Manager class takes on several important roles in an OOP system:
>
>   * **Manager:** It is the central authority responsible for the creation, lifecycle, and coordination of its components. It holds the logic for the whole system
>     * collision checks, cleanup etc
>   * **Factory:** It contains the methods (like `createComponent()`) that use the `new` keyword to manufacture new instances of its associated class
>   * **Initiator:** When the Manager calls a method on one of its components (`element.updateState()`), the Manager is acting as the **Initiator**, sending a message to the Component to perform an action. This delegation simplifies the main program

  * **Key Method: The Factory Method (Dynamic Instantiation):** The Manager needs a method that acts as a factory. 
      * This method uses the `new` keyword to create a new Component object and stores it in its internal array


```javascript
//Inside the Manager class:
createComponent() {
  // 1. Manager (Initiator) creates a new instance of Component
  let newElement = new Component(this.x, this.y, 100) 
  // 2. add the new instance to its internal collection
  this.elements.push(newElement)
}
```

  * **Key Method: The Delegation Method:** The Manager's display/update method delegates responsibility to the Component objects.
    * It iterates through its array, calling the individual methods of each `Component`

### **Implementation and Cleanup**

The power of composition is evident in the Manager's method, which handles the entire lifecycle of the components by iterating and delegating

```javascript
// Inside the Manager class:
runElements() {
  // 1. Loop and delegate rendering/behavior
  for (let element of this.elements) { //for each loop
    element.display()     // Tell the component to draw itself
    element.updateState() // Tell the component to update its state
  }

  // 2. Cleanup: The Manager keeps only the components that are still active.
  //this removes dead elements from the array, saves space in
  //this.elements = this.elements.filter(element => element.life > 0) //stollen arrow function...
  // this should be the same thig?
  this.elements = this.elements.filter(function (element) {
    return element.life > 0;
  })
}
```

> [!TIP]
> By using composition, the sketch.js only has to interact with a single `Manager` object, keeping the `draw()` loop clean and readable

```javascript
let myManager

function setup() {
  createCanvas(600, 400)
  // Instantiate the Manager
  myManager = new Manager(100, 200)
}

function draw() {
  background(50)
  // The main sketch only interacts with the Manager
  myManager.move() // Assuming a move method exists
  myManager.createComponent() 
  myManager.runElements() 
  // The Manager handles the rest
}
```
