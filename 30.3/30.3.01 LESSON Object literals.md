## 1. The Problem: Procedural Code Becomes Messy

When using individual, separate variables for each piece of data, managing even a small number of objects quickly becomes difficult.

### Example: One Ball Using Procedural Code

```javascript
let ballX = 100;
let ballY = 100;
let ballSize = 30;
let ballColor = "pink";

function setup() {
  createCanvas(400, 400);
}

function draw() {
  background(220);
  fill(ballColor);
  ellipse(ballX, ballY, ballSize);

  // Movement
  ballX = ballX + 2;
}
```

> [!WARNING]
>
> ### **Scaling Issues**
>
> Try adding 2,3,4....  by making variables like `ball2X`, `ball2Y`, etc. You will soon notice the code gets repetitive, rigid, and hard to organize.
>
> **Key idea:** When data belongs together (position, size, color, movement), keeping it separated makes the code fragile

-----

## 2. Transition: Using an Object Literal

An **object literal** solves the scaling problem by storing related information (**properties**) and behaviour (**methods**) together within a single unit.

### Example: Ball Using an Object Literal

```javascript
let ball1 = {
  //PROPERTIES aka your data
  x: 100,
  y: 100,
  size: 30,
  color: "pink",

  // METHODS aka how it hebaves
  move: function() {
    // 'this' refers to the object calling the method (ball1)
    this.x = this.x + 2;
  },

  display: function() {
    fill(this.color);
    ellipse(this.x, this.y, this.size);
  }
};

function setup() {
  createCanvas(400, 400);
}

function draw() {
  background(220);
  ball.move();
  ball1.display();
}
```

> [!NOTE]
> 
>   * **Properties** store data, `x`, `y`, `size`
>   * **Methods** store behaviour, `move()`, `display()`
>   * The **`this`** keyword refers to the object calling the method (`ball1` in this case). It ensures you are updating the correct object's data.
>
>
### Using the Object in the Main Loop

```javascript
function draw() {
  background(220);
  ball1.move();
  ball1.display();
}
```

## 3. Why This Matters: Encapsulation

The core concept demonstrated here is **Encapsulation**.

> [!IMPORTANT]
>
> ### **Encapsulation**
>
> **Encapsulation** is the principle of grouping related data, aka **Properties**, and the actions, **Methods**, that do something with that data  together into a single, cohesive unit (the object)
>
> * **Modularity**: You can fix one part (like a "Wheel" object) without breaking the whole "Car"
> * **Reusability**: Once you define a "Person" object, you can create thousands of individual people without rewriting the code.
> * **Organization**: It keeps related data and functions tucked away in the same container. 
> 

-----

## 4. TL;DR

| Concept | Definition | Example |
| :--- | :--- | :--- |
| **Object Literal** | A single object written directly in code using `{}`. | `let ball = { x: 10, y: 20 }` |
| **Property** | A value stored inside an object. | `ball.color` |
| **Method** | A function stored inside an object. | `ball.move()` |
| **`this`** | Refers to the object the method belongs to (the object currently running the code). | `this.x = this.x + 1;` |
