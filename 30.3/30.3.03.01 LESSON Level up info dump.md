# 1. Why OOP Exists

### The Problem

When programs grow in size, using many separate variables becomes difficult to manage. 
* if a game contains several moving shapes, using variables like `ball1X`, `ball1Y`, `ball1Speed`, `ball2X`, `ball2Y`, and so on quickly becomes unmanageable
* Procedural code does not organize data and does not scale well

### The OOP Solution

Object-Oriented Programming solves this by grouping related information and behaviours together into a single structure called an **object**. Each object holds:

* Data (called **properties**)
* Functions that act on that data (called **methods**)

This approach is called **encapsulation**, and it helps keep code organized, reusable, and easier to maintain.

---

# 2. What a Class Actually Is

A **class** is a blueprint for creating multiple similar objects.

A class is not an object itself. It is a definition that describes:

* What data each object will have
* What actions each object can perform

Once a class is defined, you can create multiple independent objects from it using the `new` keyword. 
* Each new item is a new **instance**

---

# 3. The Constructor

The **constructor** is a special function inside a class that runs one time when a new object is created. It sets up the initial data for that object.
* sort of like `setUp()` in p5js... you set your rules and define variables etc

```javascript
class BouncingBall {
  constructor(startX, startY, startSize, startSpeed) {
    this.x = startX
    this.y = startY
    this.r = startSize / 2
    this.speedX = startSpeed
  }// end con
}
```

### Why do we need a constructor?

* It makes sure every object starts with a complete set of values
* It lets you to create unique objects by passing **parameters** 
* It guarantees consistent structure across all objects created from the class

Without a constructor, your objects would not have an organized way to receive their starting values.

---

# 4. ABout Properties

Properties hold the object's **state**.
* An object's state is its internal data at any moment in time.
  * Position
  * Size
  * Speed
  * Color
  * Health
  * Score

Every object created from the same class has its own independent copy of these properties.
* If you create three `BouncingBall` objects, each one maintains its own state. Changing one does not affect any others

---

# 5. Methods

Methods define **behaviours** an object can perform.
They allow objects to act on their own data using the `this` keyword.

```javascript
display() {
  ellipse(this.x, this.y, this.r * 2)
}
```

* They keep the logic related to the object **inside** the object
* They prevent repeated code
* They make your objects more reusable, predictable, and easy to modify

---

# 6. the `this` key word

Inside a class, `this` always refers to the *specific object instance* that is currently running the code.

`this.x`:

* “Use the x value that belongs to this particular object”

Without `this`, the code would not know which object’s data to reference.

---

# 7. The `new` key word

The `new` keyword creates an actual instance of a class.
* It triggers the constructor and allocates memory for the new object


```javascript
let ballA = new BouncingBall(100, 200, 40, 3)
```

**Without `new`, you do not create a real object.**
* The class would only exist as an unused blueprint.


# 8. Naming Standards in OOP

### Class Names Use PascalCase

PascalCase means every word starts with a capital letter

```
BouncingBall
PlayerCharacter
EnemyShip
ScoreTracker
```

* This visually separates classes from variables and functions
* This makes code easier to read and helps developers quickly understand what each identifier represents
    * everything else is camelCase

This standard is used across JavaScript and most modern languages
