## 1. Efficiency Principles

### 1. Programmer Efficiency: the Human Cost  aka punnny meat based software
Programmer efficiency deals with how easily a human can write, read, and debug code. 

* **Recursion:** Recursion follows a top-down logic. In algorithms like Merge Sort, the code mirrors the way we think about the problem:
  * "To sort a whole list, I just sort the two halves." This reduces the mental load on the developer.
* **Iteration:** Iterative versions of complex sorts require spaghetti logic, manually managing indices, maintaining custom stacks, and handling nested loops.
  * This increases the likelihood of off-by-one errors and makes the code harder for a teammate to maintain.

---

### 2. Space Efficiency: The Memory Footprint
Space efficiency refers to the extra memory an algorithm needs to run, also known as **Auxiliary Space**.

* **The Call Stack:** Every time a recursive function calls itself, the computer creates a **Stack Frame**.
    * This frame stores the function’s local variables and the return address (where the computer should go when the function finishes). 
    * If you sort a list with 1,000,000 elements using recursion, you might create a stack a thousand levels deep. If the memory allocated for the stack is full, the program crashes with a **Stack Overflow**.
* **In-Place vs. Auxiliary:**
    * **Bubble Sort** is in-place O(1) because it only needs one tiny temporary variable to swap elements. 
    * **Merge Sort** is not in-place O(n) because it creates brand-new lists during the merge process.
      * If you are sorting a 4GB file, Merge Sort might need another 4GB of RAM just to hold the temporary halves.

---

### 3. Time Efficiency: Scaling with Big O
Time efficiency is about growth rate rather than raw seconds. We use Big O Notation to predict how much slower the program gets as the input size n increases.

* **The Quadratic Trap O(n^2):** In iterative sorts like Bubble Sort, you have a loop inside a loop. If you double the number of items, the work quadruples.
    * For 10 items, you do 100 operations.
    * For 1,000 items, you do 1,000,000. 
* **The Logarithmic Advantage O(n log n):** Recursive sorts like Merge Sort and Quick Sort use Divide and Conquer. By splitting the list in half repeatedly, they significantly reduce the number of comparisons. 
    * To sort 1,000,000 items, Bubble Sort takes 1 trillion operations.
    * Merge Sort takes only about 20 million operations.

## 2. Quick Sort: The Pivot Strategy

Quick Sort is a fast sort that relies on the concept of **Partitioning**.

### The Partition Helper (Non-Recursive)
To partition a list:
1. **Select a Pivot:** Use the first value in the list.
2. **Filter:** Loop over all other values:
    * Values less than or equal to the pivot go into a **smaller** list.
    * Values greater than the pivot go into a **larger** list.
3. **Result:** Return the smaller list, the pivot, and the larger list.

#### ex: `partition([3, 2, 5, 1, 4])`
* Pivot: 3
* Smaller values: [2, 1]
* Larger values: [5, 4]
* Returns: ([2, 1], 3, [5, 4])

### The Recursive Algorithm
1. **Base Case:** If the list has 0 or 1 elements, it is already sorted. Return it.
2. **Recursive Case:** * Partition the list into smaller, pivot, and larger.
    * Recursively call quickSort on smaller.
    * Recursively call quickSort on larger.
    * Return sortedSmaller + [pivot] + sortedLarger.

> [!WARNING]
> **Quick Sort Disadvantage:**
> If the list is already sorted or nearly sorted, picking the first element as the pivot is inefficient.
> In these cases, Quick Sort can degrade to **O(n^2)**.
>

## 3. Merge Sort: 

Merge Sort is reliable. It is fast for any list, regardless of whether it is sorted, reversed, or random. 
It relies on the concept of **Merging** ... go figure

### The Merge Helper (Non-Recursive)
To merge two already-sorted lists (L and M):
1. Start with an empty list N.
2. Compare the first element of L to the first element of M.
3. Place the smaller value into N and move to the next item in that list.
4. Once one list is empty, append all remaining values from the other list.

**ex:** Merge L = [2, 5] and M = [1, 6]
1. Compare 2 and 1 -> N = [1]
2. Compare 2 and 6 -> N = [1, 2]
3. Compare 5 and 6 -> N = [1, 2, 5]
4. L is empty -> Append remainder of M -> N = [1, 2, 5, 6]

### The Recursive Algorithm
1. **Base Case:** If the list has 0 or 1 elements, return it.
2. **Recursive Case:** * Divide the list into two halves: left and right.
    * Recursively call mergeSort on the left.
    * Recursively call mergeSort on the right.
    * Merge the two now-sorted halves and return the result.

## 4. Comparison and Choice

> [!IMPORTANT]
> While Quick Sort is often slightly faster in practice for random data, **Merge Sort** is generally preferred in critical systems because it guarantees O(n log n) time complexity and is a Stable sort (it preserves the order of equal elements).

### Efficiency Summary Table

| Metric | Bubble Sort (Iterative) | Quick Sort (Recursive) | Merge Sort (Recursive) |
| :--- | :--- | :--- | :--- |
| **Strategy** | Comparing Neighbors | Partitioning | Splitting and Merging |
| **Average Time** | O(n^2) | O(n log n) | O(n log n) |
| **Worst Case** | O(n^2) | O(n^2) | O(n log n) |
| **Space** | O(1) (In-place) | O(log n) (Stack) | O(n) (Auxiliary) |
| **Best Case** | O(n) (with flag) | O(n log n) | O(n log n) |
