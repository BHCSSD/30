# 7.1.3 More Recursive Code

Writing recursion is often about making the right choices. Today, we will look at how to pick the best **base case**, when you might need more than one, and how to use recursion for things other than numbers.

---

## Choosing a Base Case
For many problems, there is more than one way to stop the recursion. Let’s look at `sumInRange(lo, hi)`, which adds all numbers from `lo` to `hi`.

### Option 1: Stop at the last number
If `lo` and `hi` are the same (like `sumInRange(5, 5)`), the answer is just the number itself.
* **Base Case:** `if lo == hi: return lo`

### Option 2: Stop when the range is empty
If we let `lo` keep increasing, it will eventually become larger than `hi`. A range where the start is bigger than the end (like `sumInRange(6, 5)`) has a sum of 0.
* **Base Case:** `if lo > hi: return 0`

### Which is better?
Both work, but **Option 2** is slightly better. This is called **defensive programming**. If someone accidentally calls `sumInRange(10, 5)`, Option 2 will safely return 0, while Option 1 might crash with a stack overflow because `lo` would skip right past `hi` and keep counting forever.

## Multiple Base Cases: The Fibonacci Problem
Sometimes, one "stop sign" isn't enough. Let’s look at the Fibonacci sequence code:
* **Recursive Rule:** `fib(n) = fib(n - 1) + fib(n - 2)`

If we only had one base case for `n == 0`, we would have a problem:
1. To find `fib(1)`, the rule asks for `fib(0)` and `fib(-1)`.
2. `fib(0)` stops correctly, but `fib(-1)` is not a base case.
3. The code will keep subtraction forever: `fib(-2)`, `fib(-3)`, etc., until it crashes.

**The Fix:** We need to cover every possible "exit" the subtraction could hit. Since we subtract by both 1 and 2, we need two base cases:

```python
def fib(n):
    if n == 0:
        return 1
    elif n == 1:
        return 1
    else:
        return fib(n - 1) + fib(n - 2)
```

## Recursion with Lists
Recursion isn't just for math; it works for data like lists too! Imagine a function `listSum(L)` that adds all numbers in a list.

### The Recursive Case
Think of a list like `[3, 7, 4, 5]`. You can look at it as:
**The first number (3) + The sum of the rest of the list ([7, 4, 5])**

### The Base Case
Every time we call the function, the list gets smaller. Eventually, the list will be empty `[]`. The sum of an empty list is 0.

```python
def listSum(L):
    if len(L) == 0:
        # Base Case: The list is empty
        return 0
    else:
        # Recursive Case: First element + sum of the rest
        return L[0] + listSum(L[1:])
```
