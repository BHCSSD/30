The **Greatest Common Divisor (GCD)** of two integers `x` and `y` is the largest int that divides both **without leaving a remainder** 

---

## 1. The Brute Force Approach
Find the GCD is to check every possible divisor manually.

* **How it works:** Iterate through every integer from 1 up to the smaller of the two numbers ($\min(x, y)$).
* **The Check:** If a number divides both $x$ and $y$ evenly, track it. The largest one found at the end is the GCD.
* **The Flaw:** This method is **computationally expensive**. 
    * If you are finding the GCD of two very large numbers (like $10^{14}$ and $10^{14}+1$), the loop will run trillions of times.
    * In many environments, this will cause a "timeout" because the CPU cannot finish the calculations fast enough.

```python
def gcd(x, y):
    x, y = abs(x), abs(y)
    
    # Base case where one number is 0
    if x==0:
      return y
    if y == 0:
      return x
   
    smaller = min(x, y)  #GCD cant be larger than the smaller of the two numbers
    bestDivisor = 1
    
    # Loop from 1 up to the smaller number inclusive
    for i in range(1, smaller + 1):
        if x % i==0 and y % i==0:
            best_divisor = i  # Update whenever we find a common divisor
            
    return bestDivisor
```

## 2. Euclid’s Algorithm
> [!NOTE]
> Invented over 2,500 years ago, Euclid’s method relies on a mathematical observation: `gcd(x, y) = gcd(y, x % y)`
> ### Why it’s Faster
> Instead of subtracting 1 in every loop, this method uses the **remainder** (the modulo operator `%`).
> * This reduces the size of the numbers drastically in every single step, allowing the algorithm to "leap" toward the answer.
> * Because of mod, it skips all non divisable nums

### `gcd(50, 20)`
1.  **Step 1:** `gcd(50, 20)` calculate `50 %20`  is **10**.
2.  **Step 2:** `gcd(20, 10)` calculate `20 %10`  is **0**.
3.  **Step 3:** `gcd(10, 0)`  since `y` is now 0, the answer is **10**.


---

## 3. GCD Recursively
Since the algorithm repeats the same logic on smaller and smaller numbers, it is a perfect candidate for **recursion**.

* **The Base Case:** When `y` reaches 0, the GCD is `x`.
* **The Recursive Step:** Call the function again, passing `y` as the new `x`, and `x%y` as the new `y`

```python
def gcd(x, y):
    # Base Case, if y==0, the GCD is x
    if y == 0:
        return x
    
    # Recursive Case: gcd(x, y) is gcd(y, x % y)  ## look at me
    return gcd(y, x % y)
```
