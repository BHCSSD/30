# 30.4.02 LESSON  7.1.2 Writing Recursive Code

Now that you know how to **think** recursively, it is time to write the code. We will use the factorial example from the last lesson. As a reminder, our rule was: $factorial(n) = n * factorial(n - 1)$.

---

### The Danger: Infinite Recursion
If we translate that rule directly into Python, we run into a major problem:

```python
def factorial(n):
    # A first (but broken) attempt
    return n * factorial(n - 1)

print(factorial(3))
```

**What happens?**
1. `factorial(3)` calls `factorial(2)`
2. `factorial(2)` calls `factorial(1)`
3. `factorial(1)` calls `factorial(0)`
4. `factorial(0)` calls `factorial(-1)`... and it never stops!

This is called **Infinite Recursion**. Eventually, the computer runs out of memory to keep track of all these calls. This crash is called a **Stack Overflow**. In Python, you will see the error: `RecursionError: maximum recursion depth exceeded`.


### The Solution: The Base Case
To fix the crash, we need an "exit" or a "stop sign." This is called a **Base Case**. It is a simple version of the problem that can be answered immediately without calling the function again.

For factorial, we know that $0! = 1$. So, if $n$ is 0, we just return 1.

```python
def factorial(n):
    if n == 0:
        # Base Case: Stop here!
        return 1
    else:
        # Recursive Case: Keep going!
        return n * factorial(n - 1)
```

Now, when `factorial(1)` calls `factorial(0)`, the function sees that $n == 0$, returns 1, and the chain of math finally finishes.

---

### Practice: Finding the Base Case

**1. Power Function ($b^e$):**
* **Recursive Case:** `b * power(b, e - 1)`
* **Base Case:** When the exponent $e$ is 0, any number to the power of 0 is 1. 
* **Return:** `if e == 0: return 1`

**2. Sum to N:**
* **Recursive Case:** `n + sumToN(n - 1)`
* **Base Case:** When $n$ is 0, the sum is 0.
* **Return:** `if n == 0: return 0`

### Checkpoint 2: Sum in Range
How can you frame `sumInRange(lo, hi)` recursively?
* **Hint:** Our rule is `lo + sumInRange(lo + 1, hi)`. Since `lo` is getting bigger every time, it will eventually catch up to `hi`.

**What is the best base case?**
1. **if lo == hi: return lo** (Correct: When the start and end are the same, the sum is just that number.)
2. if lo == hi + 1: return lo
3. if lo == hi - 1: return 0
4. if lo == hi: return 0

### The General Form of Recursion
Every recursive function should follow this template:

```python
def recursiveFunction(parameters):
    if (this is the base case):
        # Stop and return a simple value
        return value
    else:
        # Make the problem smaller and call the function again
        return (something) + recursiveFunction(smaller_parameter)
```



---

### How to Build a Recursive Solution
1. **Start with the Recursive Case:** Ask yourself, "How can I make this problem one step smaller?" (Example: $n!$ is just $n * (n-1)!$).
2. **Assume it Works:** Pretend the smaller version of the function already knows the right answer.
3. **Find the Base Case:** What is the smallest, simplest version of this problem where I don't need to do any more math? (Example: $0!$ is 1).
4. **Bridge the Gap:** Make sure your recursive calls are actually moving closer to the base case. If your base case is 0, but your recursive call adds 1 every time, you will never reach the end!
